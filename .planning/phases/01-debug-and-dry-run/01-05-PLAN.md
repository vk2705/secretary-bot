<planner_decisions>
**D-P7 — the override applies to reading, never to recording.**

RESEARCH.md's call-site table classifies roughly thirty sites as per-user. Applying the override to all of them would mean that completing a habit, logging a tracker reading, journalling, or completing a task while a clock is active writes a fabricated date into the user's real history — permanently, and indistinguishably from a real entry. That is the harm this plan's first prohibition names, and it is more severe than the display-level tampering the threat model already tracks, because a wrong display corrects itself on reset and a wrong stored date does not.

The rule, applied once and stated here so the executor never has to guess:

> **The simulated clock changes what the bot believes the time is when it compares or displays. It never changes what gets stamped onto a durable record.**

Every one of the phase's four success criteria — the deadline badge, the inactive quiet-hours window, the distant annual reminder, and the verbatim prompt — is a compare-or-display site. None of them requires a write site. So this rule costs the phase nothing and removes an entire class of unrecoverable harm.

Two further sites are excluded for a different reason, recorded as the second prohibition: the one-shot reminder delay arithmetic and the startup catch-up window compute *real scheduling times*. Routing them through the override would schedule a real reminder years away or in the past, breaking the user's real reminders long after the debug session ended.

This narrows RESEARCH.md's recommendation. It is a planner decision, made deliberately, and it is recorded rather than applied silently. **Reversibility: reversible** — a later phase can widen the worklist if a concrete need appears, and the exclusion list below is the record of what was left out and why.
</planner_decisions>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Stored override → every compare-and-display path | One stored value silently changes what roughly sixteen call sites believe the date is |
| Compare-and-display paths → durable-write paths | The boundary this plan's central rule defends: a leak across it writes a fabricated date into the user's real history |
| Override → real scheduler arithmetic | One-shot reminder delays and startup catch-up windows compute real future times; an override reaching them breaks real reminders |
| Owner's simulated view → owner's real view | While a clock is active, the owner's own deadline badges and quiet hours are not the real ones |
