This is RESEARCH.md Open Question #2's recommendation (option b). Rationale: ROADMAP.md declares this code must not be revisited concurrently by any other phase this milestone, so the thorough extraction is done once rather than leaving a registry hack for a second pass. **Reversibility: costly** — wide mechanical change in a single 4238-line file that no other phase may touch concurrently.
- **D-P3 (reminder targeting):** `/debug fire reminder <n>` uses the 1-based index from `/remind list`, never the UUID (RESEARCH.md Pitfall 4). **Reversibility: reversible.**
- **D-P4 (owner-gate spelling):** the `broadcast_cmd` form that explicitly tests for an unset `MY_CHAT_ID` first, not the `admin_stats` form (RESEARCH.md Pitfall 5 — fails closed and is self-documenting). **Reversibility: reversible.**
- **D-P5 (real jobs during a debug clock):** real APScheduler jobs are **not** suppressed while a simulated clock is active (RESEARCH.md Open Question #1 / assumption A4). Rationale: suppression introduces a re-arm bug class (forgetting to reschedule on reset); a stray real message during a debug session costs a single-user bot nothing. **Reversibility: reversible.**
- **D-P6 (clock storage, lifecycle and breadth):** see plans 01-04 and 01-05.

Where research suggested something narrower, the later locked decision wins: ROADMAP.md's planning note scopes the time refactor to "every job closure", but CONTEXT.md's **D-01** (ambient, persistent override visible to ordinary commands) was decided later and is authoritative. Plan 01-05 implements the ambient breadth.
