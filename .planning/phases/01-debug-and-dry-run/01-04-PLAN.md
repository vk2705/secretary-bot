<planner_decisions>
**D-P6 — clock storage, lifecycle, carrier and breadth.** CONTEXT.md left four sub-questions open under Claude's Discretion. Resolved here for the whole phase:

- **Carrier — the user dict, not a threaded parameter.** The override is written to SQLite `user_prefs` and overlaid onto the user dict by `get_user()`, exactly as `timezone` already is (RESEARCH.md Pattern 4; CLAUDE.md documents the precedent). Every helper and job body that already receives a `user` dict — `_is_quiet_now`, `_is_muted`, `_get_streak`, `build_system_prompt`, all six job runners, every command handler — therefore needs no signature change at all. Only three helpers that receive neither a user nor a chat id gain an optional parameter. Rejected: threading `chat_id` through every call chain, which RESEARCH.md names as the anti-pattern and which would touch roughly fifty call sites instead of three signatures. **Reversibility: reversible.**
- **Storage — SQLite `user_prefs`, not `state.json` alone.** RESEARCH.md assumption A1. It survives a `state.json` overwrite or `/import`, needs no schema migration, and is excluded from `/export` by construction because `export_data` builds an explicit whitelist. **Reversibility: reversible.**
- **Lifetime — survives restart, expires after 12 hours.** RESEARCH.md assumption A2 recommended a bounded expiry and flagged it as a policy call. CONTEXT.md names the risk directly: a forgotten simulated clock silently skews the owner's own real deadline badges and quiet hours. Twelve hours is chosen so a clock set during a morning debugging session is gone before that evening's check-in, while a session lasting a working day never has the clock vanish mid-test. The expiry is evaluated against the real wall clock, never the override, so an override cannot extend itself. **Reversibility: reversible.**
- **Input format — anything `datetime.fromisoformat` accepts.** RESEARCH.md Open Question #3. This covers both `YYYY-MM-DD` for date-level tests and `YYYY-MM-DDTHH:MM` for quiet-hours tests with one parser and no new syntax, matching every other ISO field in this codebase. **Reversibility: reversible.**
- **Semantics — purely additive.** With no override set, each new helper returns exactly what the standard-library call it replaces returns, including keeping `date.today()`'s existing server-local semantics. Correcting `date.today()` to be user-timezone-aware would be a real improvement but it is a behaviour change for every user, unrelated to debug tooling, and it must not ride along silently inside this phase. **Reversibility: reversible.**
</planner_decisions>
