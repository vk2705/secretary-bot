## Directory Purposes

**`/` (root):**
- Purpose: Main source code and configuration
- Contains: Single-file bot app, separate MCP server, requirements, working state
- Key files: `bot.py` (4200 lines, single-threaded event loop), `mcp_server.py` (direct store access)

**`/tests/`:**
- Purpose: Test suite for bot.py
- Contains: Unit tests, LLM sanity checks, tool-use verification tests
- Key files: `test_bot.py` (600+ lines, 3 test sections)

**`/.planning/codebase/`:**
- Purpose: Codebase analysis documents (generated by gsd-map-codebase)
- Contains: ARCHITECTURE.md, STRUCTURE.md, CONVENTIONS.md, TESTING.md, CONCERNS.md
- Auto-generated: Yes (via GSD tools)

**`/.claude/`:**
- Purpose: Claude Code workspace configuration
- Contains: settings.local.json (project overrides), GSD framework, custom scripts
- Special: Read-only except settings.local.json

## Naming Conventions

**Files:**
- `bot.py` — Main application (snake_case)
- `mcp_server.py` — MCP server (snake_case)
- `test_bot.py` — Test module (test_ prefix)
- `.env` files — Configuration secrets (uppercase vars inside)
- `*.md` — Documentation (UPPERCASE or TitleCase for filenames)

**Functions:**
- Public: `load_state()`, `save_state()`, `chat()`, `get_user()` (snake_case)
- Internal: `_execute_tool()`, `_task_text()`, `_parse_local_time()` (leading underscore)
- Handlers: `start()`, `handle_message()`, `show_tasks()` (verb + noun)
- Helpers: `db_add_note()`, `db_get_journal()` (db_ prefix for database ops)
- Async: `async def _execute_tool()`, `async def chat()` (async keyword)

**Variables:**
- Module-level: `RATE_LIMIT`, `MAX_HISTORY`, `TOOLS`, `DEFAULT_MODEL` (UPPERCASE for constants)
- State keys: `"tasks"`, `"history"`, `"checkin_enabled"`, `"timezone"` (lowercase, snake_case, match user dict schema)
- Job names: `"checkin_morning_12345"`, `"reminder_12345_uuid"` (pattern: {type}_{user_id}_{optional_id})

**Types:**
- User: `chat_id: int` (Telegram numeric ID)
- Task: `str` or `dict` ({"text": "", "due": "", "recur": "daily|weekly|monthly"})
- Reminder: `dict` ({"id": uuid, "time": "HH:MM", "message": "", "reason": "", "once": bool})
- Tracker: `dict` ({"name": str, "unit": str, "log": [{"ts": ISO8601, "value": float}]})
- Tool result: `dict` (always JSON-serializable, includes "success" or "error" key)

## Where to Add New Code

**New Feature / User-Facing Command:**
1. Add command name to `TOOLS` list if it needs tool-calling (`bot.py:641+`)
2. Add `CommandHandler` in `main()` (`bot.py:4160-4225`)
3. Write handler function (e.g., `async def my_command(update, context)`) near other handlers in `bot.py`
4. If handler needs to modify state, call `chat()` or update state dict + `save_state(state)` directly
5. Write tests in `tests/test_bot.py` (unit test for logic, NL test if using tool-calling)

**New Tool (for LLM to invoke):**
1. Add tool schema to `TOOLS` list (`bot.py:641+`) with name, description, parameters
2. Add handler in `_execute_tool()` if/elif chain (`bot.py:1063+`)
3. Return `{"success": True, ...}` or `{"error": "..."}` (JSON-serializable dict)
4. If tool modifies state: call `save_state(state)` or database helper before returning
5. Write tests: unit test to verify return value, NL test to verify LLM invokes it

**New Scheduled Job (recurring automated task):**
1. Add job creation function like `schedule_user_checkins()` (`bot.py:1857+`)
   - Use `app.job_queue.run_daily()` or `run_once()` or `run_repeating()`
   - Capture user_id via closure parameter to `_job()` inner function
   - Respect quiet hours + mute status before sending
2. Call job creator in `_execute_tool()` when user enables feature (e.g., `set_timezone`, `set_checkins`)
3. Add job recovery in `restore_all_jobs()` (`bot.py:2156+`) — recreate job from state on restart
4. Log job fire time: `db_log_job(str(chat_id), "job_type")` to track missed jobs

**New Database Table/Column:**
1. Add schema to `_init_db()` CREATE TABLE or ALTER TABLE (`bot.py:88-165`)
2. Write helper functions: `db_add_*()`, `db_get_*()`, `db_remove_*()` following existing pattern (`bot.py:213-450`)
3. Use `with _db() as con:` context manager to ensure connections are closed
4. For long-lived data (notes, journal, memory): store in bot_memory.db
5. For user prefs: store in user_prefs table (survives state.json overwrites)

**New State Field:**
1. Add key to `_new_user()` defaults (`bot.py:466-490`)
2. `get_user()` will auto-forward-fill it on next access
3. If per-user and critical (like timezone): also store in SQLite user_prefs and overlay in `get_user()`
4. Document in CLAUDE.md state schema section

**Test: Unit Test (pure logic, no API):**
- Location: `tests/test_bot.py` in `class Test*` (e.g., `TestTaskHelpers`)
- Pattern: Import bot, call function, assert return value
- Example: `assert bot._task_text("Task text") == "Task text"`
- Run: `pytest tests/test_bot.py -v -k "not sanity and not nl"`

**Test: LLM Sanity Check:**
- Location: `tests/test_bot.py` with `@pytest.mark.sanity` decorator
- Pattern: Call `run(bot.chat(chat_id, message))`, verify non-empty response
- Requires: Real API key (OPENAI_API_KEY or GROQ_API_KEY)
- Run: `export $(grep -v '^#' env | xargs) && pytest tests/test_bot.py -v -k sanity`

**Test: Natural Language Tool-Use (LLM invokes tools):**
- Location: `tests/test_bot.py` with `@pytest.mark.nl` decorator
- Pattern: Call `run(bot.chat(chat_id, NL_prompt))`, verify tool was invoked (spy on mock, check state change)
- Requires: Real API key + stubs for Telegram message sending
- Run: `export $(grep -v '^#' env | xargs) && pytest tests/test_bot.py -v -k nl`

## Production Deployment

**File Layout on Server:**
```
/path/to/secretary-bot/
├── bot.py              # Deployed version
├── mcp_server.py       # (optional) separate MCP process
├── requirements.txt    # Frozen for reproducible deploys
├── state.json          # Live user data
├── bot_memory.db       # Live SQLite database
├── env                 # (sourced before running)
└── nohup.out           # Background process log
```

**Startup Script:**
```bash
cd /path/to/secretary-bot
export $(grep -v '^#' env | xargs)
nohup python3 bot.py > nohup.out 2>&1 &
```

**MCP Server (if serving claude.ai):**
```bash
export $(grep -v '^#' mcp_remote.env | xargs)
export MCP_TRANSPORT=remote
nohup python3 mcp_server.py > mcp_server.log 2>&1 &
```
